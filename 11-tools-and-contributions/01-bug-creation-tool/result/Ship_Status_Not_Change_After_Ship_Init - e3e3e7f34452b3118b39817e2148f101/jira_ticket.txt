*Root Cause Analysis:*

**Issue Type:** Backend Configuration Issue - CID Routing Mismatch

**Technical Details:**
The issue occurs in the `sellerplatform-gatewayacl-staging-sg` service during the authentication flow for shipment initialization. The service is deployed in Singapore (sg) environment but is receiving requests with Indonesia (id) CID flag, causing a mismatch.

**Error Chain:**
1. Frontend sends request to `/api/v3/shipment/init_order` with Region-Id: ID header
2. Request is routed through `mall-sellergatewayunification-staging-global` gateway
3. Gateway forwards to `sellerplatform-gatewayacl-staging-sg` (Singapore environment)
4. Gateway ACL service detects CID mismatch: flag=id but env=sg
5. Spex error code 10019 is triggered
6. Authentication check fails, blocking the shipment initialization

**Service Chain:**
- mall-sellergatewayunification-staging-global (Entry point)
  → sellerplatform-gatewayacl-staging-sg (Authentication - **ERROR HERE**)
  → seller-fulfilment.order.i.staging.marketplace.co.id (Target service)

**Configuration Issue:**
The `seller_cid_routing` plugin in the gateway is not correctly routing ID region requests to the ID-specific backend services. Instead, requests are being sent to the SG environment services, causing the CID validation to fail.

**Affected Components:**
- Service: sellerplatform-gatewayacl
- Environment: staging-sg (should be staging-id for ID requests)
- Plugin: seller_cid_routing-100
- API: seller.platform.gateway_acl.get_seller_center_authentication

**Impact Assessment:**

- Scope: All ID sellers in staging environment
