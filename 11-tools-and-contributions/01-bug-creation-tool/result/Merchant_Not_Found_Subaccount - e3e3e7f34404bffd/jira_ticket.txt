*Initial Judgment / Root Cause Analysis:* Backend issue / Unknown

Based on the symptoms, this appears to be a backend issue related to one or more of the following:

1. **Database Routing/Query Issue**: The merchant listing API may be querying the wrong database shard, or there's a read/write split issue where merchants are written to primary DB but queries read from an out-of-sync replica.

2. **Cache Issue**: Merchant list may be cached with stale data (empty result), and cache invalidation is not working properly after merchant creation.

3. **Permission/RBAC Issue**: The user account may not have proper permissions to view merchants, or RBAC rules are filtering out all merchants incorrectly.

4. **Data Visibility Issue**: Merchants may be created with incorrect status flags (inactive, deleted, pending) that exclude them from the default listing query.

5. **Search Index Issue**: If using Elasticsearch or similar, the search index may not be synchronized with the database.

6. **Query Filter Issue**: The listing API may have default filters (date range, status, region) that exclude the newly created merchants.

**Recommended Investigation Steps:**
- Check database directly to verify merchants exist: `SELECT * FROM merchant_table ORDER BY created_at DESC LIMIT 10`
- Review subaccount service logs for API errors around the time of access
- Test merchant listing API directly with Postman/curl to see raw response
- Check user permissions and RBAC configuration
- Verify cache service health and cache keys
- Review database replication status and query routing configuration
