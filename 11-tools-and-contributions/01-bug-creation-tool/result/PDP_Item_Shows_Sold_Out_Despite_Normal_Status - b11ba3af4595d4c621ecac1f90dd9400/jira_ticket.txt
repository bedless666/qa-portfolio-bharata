*Initial Judgment / Root Cause Analysis:* Backend issue - PDP Service

Based on log analysis, the root cause is in the PDP service's logic for determining item availability. The issue chain:

1. **Admin & BassItemInfo Status = NORMAL** ✅
   - Seller Center admin shows item status is NORMAL
   - bass.shop.batch_get_shop_with_ext_info returns success (code: 0)
   - Item data from backend services shows normal status

2. **Logistics Planning Fails** ❌
   - Service: prefulfilment-fulfilmentplanning-test-la
   - Error: "no_valid_seller_channel_id" 
   - Warning: "unknown_retcode" (retcode=-10501)
   - Shipping fee calculation fails with ShippingFeeCalculationError

3. **PDP Incorrectly Marks as Sold Out** ❌
   - PDP service receives logistics failure
   - Instead of showing "shipping not available" or similar error
   - PDP sets "abnormal_status": "sold_out"
   - This is misleading because item is NOT sold out - it has logistics configuration issues

**Root Cause**: PDP service is incorrectly interpreting logistics/shipping failures as "sold_out" status. When shipping fee calculation fails or no valid shipping channels are found, PDP should either:
- Show a more accurate status like "shipping_not_available" 
- Display an error message about shipping configuration
- NOT mark the item as "sold_out" when the actual item status is NORMAL

**Technical Details**:
- Logistics config service returns empty channel list (mplogistics-logisticsconfig-test-la)
- LPS API fails with error -10501 (ShippingFeeCalculationError) 
- COD validation fails with error -20213 (CODExtraShippingFeeNotMatch)
- PDP interprets these logistics errors as item being "sold_out"

**Impact**: This creates confusion because:
- Seller sees item as NORMAL in admin ✅
- Backend APIs return item as NORMAL ✅  
- But buyer sees item as "sold_out" ❌
- The actual issue is logistics configuration, not item availability

**Suggested Fix**: 
PDP team should review the logic that sets "abnormal_status" and ensure logistics/shipping errors are handled separately from actual item availability status. Consider adding a new status like "shipping_unavailable" or showing appropriate error messaging instead of marking as "sold_out".
