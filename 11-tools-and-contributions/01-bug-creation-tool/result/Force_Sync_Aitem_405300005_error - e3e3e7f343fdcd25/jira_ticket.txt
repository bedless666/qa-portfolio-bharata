*Initial Judgment / Root Cause Analysis:* Backend issue

**Root Cause:**
The issue is caused by a timeout (error code 10004) in the `seller.seller_operation.account_health_metric_api.get_shop_listing_limit` service when called during the product lock check phase. This is a critical dependency in the SIP item sync flow.

**Error Chain:**
1. **User Action**: Force sync Aitem from Seller Center (Primary Item: 2944816227 → Affiliated Item: 3703805432)
2. **API Call**: `crossuploadbff.admin.sync_related_aitem` → `marketplace.listing.upload.crossupload.api.sync_product`
3. **Product Update**: `marketplace.listing.upload.product.update_product` is called for the affiliated shop
4. **Lock Check**: `marketplace.listing.upload.lock.check_product_lock` is invoked to validate product lock status
5. **Health Metric Check**: Calls `seller.seller_operation.account_health_metric_api.get_shop_listing_limit` to verify shop listing limits
6. **Timeout**: The health metric API times out with error code 10004 (ERROR_TIMEOUT)
7. **Propagation**: Error propagates back through the chain as 338300005 → 370200006 → 405300005

**Service Call Chain:**
```
crossuploadbff-admin (405300005)
  → crossupload.api (370200006)
    → marketplace.listing.upload.product (338300005)
      → marketplace.listing.upload.lock.check_product_lock (338300005)
        → seller.seller_operation.account_health_metric_api.get_shop_listing_limit (10004 - TIMEOUT)
```

**Additional Issues Found:**
1. **Cache Errors**: `region_sync_config:VN_KH_0` cache read failure in crossupload-api
2. **Missing Configuration**: Item attribute service shows KH region missing from unit_local_settings for attribute ID 100098
